# 从解题展示到教学讲解

先写出并验算完整题解，再设计动画。一个讲解视频应回答“为什么选择这条路”，而不仅是报出下一条公式。

## 学习节奏

- 两道独立大题优先拆成两个视频，各自有目标、条件、解法、验算和迁移练习。不要为了固定时长跳过推理。
- 每句只讲一个推理步骤；先解释关键概念，再使用它。统计题先解释柱形面积才是频率；线面角先找投影，再算角。
- 在关键问题后设置 `pause_after`（建议 3~6 秒），下一句再揭示答案。系统增加真实的无旁白时间，并保留问题字幕。
- 结尾换一个条件，让学生用刚学的方法再算一次，随后讲明答案及适用条件。

## 定理条件与依据

使用定理的那一句可声明 `theorem`，列明每个条件及其依据。`--check` 会要求这些字段完整，并输出 `build/teaching_report.txt`。

```json
{
  "zh": "条件满足，使用勾股定理求斜边。",
  "tts": "条件满足，使用勾股定理求斜边。",
  "en": "The conditions hold, so use Pythagoras.",
  "theorem": {
    "name": "勾股定理",
    "conditions": [
      {"claim": "∠C = 90°", "reason": "题目已知"},
      {"claim": "AB 是斜边", "reason": "AB 对着直角 C"}
    ],
    "conclusion": "AB^2 = AC^2 + BC^2"
  }
}
```

这是**结构检查，不是数学证明验证器**。它不会自动识别未声明的定理，也不会验证条件或结论是否真实。必须独立验算、核对报告，并把条件在 `anim.js` 的板书和图形中展示出来。报告不会自动绘制到画面。

例如用“两条线垂直”证明“线与面垂直”时，必须说明这两条线都在该平面内、相交，并且待证直线垂直于两者。只写“垂直”不够。

## 动画审阅

像素变化只说明画面在动，不能证明动画有教学意义。`motion` 仍只采样旁白段（`start` 到 `end`），不会把有意静止的思考停顿判为失败。人工审阅时检查：

1. 图形是否把当前推理关系演出来，而不是无意义晃动。
2. 辅助线与投影是否来自同一几何模型；垂足、角度和长度是否计算正确。
3. 条件、定理和结论的出现顺序是否与旁白一致。
4. 停顿期间问题是否保留，答案是否留到下一句才出现。
5. 迁移题是否满足定理的条件；改变条件后是否仍可使用原方法。

自带斜边中线模板演示了条件核对、两次思考停顿、矩形判定的中间理由，以及斜边改为十的迁移题。
